# Repertoire Width vs Decision-Space Width

**Date:** 2026-09-14  
**Status:** active Meta Brainstorm pattern

## Capability discovered

The number of available actions is not the same thing as the number of distinct problems an actor can force another system to solve.

Compact law:

> **Repertoire width need not equal decision-space width.**

A tiny repertoire can create a large decision space when the available actions occupy sharply different regimes.

```text
MAXIMUM MEASURE

MAXIMUM COMMITMENT
```

The missing middle was part of the structure.

## Transferable mechanism

Suppose an agent has only two actions, but each action changes which rules matter.

```text
ACTION A -> opponent must solve distance / entry
ACTION B -> opponent must solve commitment / collision / recovery
```

Then the opponent is not solving a two-choice menu. They are switching between two different local models of the encounter.

Therefore:

```text
LOW ACTION COUNT
+
HIGH REGIME SEPARATION
=
HIGH OPPONENT MODEL BURDEN
```

This is a heuristic relation, not a literal quantitative formula.

## Why this matters across domains

### Game design

A character may need only a few verbs if each verb changes the state relationship sharply. This helps explain why tiny combat vocabularies can feel deep when actions control different distances, timings, risks, or ownership states.

### Animation

A few semantic extrema can encode more than many weakly differentiated poses. Strongly separated states force the viewer to infer a meaningful transition.

### Interface design

A small command surface can still expose broad capability if commands operate on different layers or regimes rather than offering many near-duplicates.

### Strategy and tactics

A small force or doctrine may impose disproportionate planning burden if its available actions threaten qualitatively different response classes.

### Creative tools

Capability should not be counted only by feature quantity. A small set of composable operations can dominate a larger menu when the operations span different causal layers.

## Relation to specialization and collaboration

The HEMA source case also reinforces a separate Meta Brainstorm doctrine: a broad integrator does not need to originate every specialist truth.

Embodied specialist knowledge can enter through collaboration while one integrator preserves cross-domain coherence.

```text
SPECIALIST SENSOR
-> DOMAIN TRUTH
-> GENERALIST INTEGRATOR
-> MULTIPLE SYSTEM LAYERS CHANGE TOGETHER
```

This preserves the coherence dividend without pretending the integrator contains every specialist peak.

## What remains situated or uncertain

- The HEMA history is USER_MEMORY, not independently verified evidence.
- A bimodal policy can be exploitable. Wide regime separation does not imply universal strength.
- More actions can still be valuable when they provide genuine new regimes rather than redundant surface variety.
- 'Opponent model burden' is a conceptual heuristic, not a standardized metric.

## Falsifier / boundary test

The claim weakens when additional actions materially increase regime coverage rather than merely adding variants inside an existing regime.

A system with two extreme actions is not deep merely because it has two extremes. The actions must actually force meaningfully different responses.

## Compact pattern

```text
COUNT ACTIONS LESS.
MAP REGIMES MORE.

If two actions force two different models of reality,
the repertoire is larger than it looks.
```
