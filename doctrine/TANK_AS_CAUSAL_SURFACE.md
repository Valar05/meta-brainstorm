# Tank as Causal Surface

**Date:** 2026-09-14
**Status:** candidate cross-domain doctrine / fertile experiment seam

## Observation

The recurring tank work is not merely a repeated subject preference. Across several artifacts, the tank keeps functioning as a dense causal object:

```text
movement
+ orientation
+ timing
+ traction
+ mechanism
+ crew / responsibility
+ damage
+ consequence
```

The attraction may therefore be structural as much as aesthetic.

## Three views of the same machine

### Last Convoy — the tank as compressed control grammar

The lead vehicle continuously moves. Steering determines body orientation, sampled auto-fire direction, and the future path inherited by the convoy. Throttle changes world-time per unit distance. A tiny control vocabulary creates conflicts across several time horizons.

### Sherman Factory Floor — the tank as inspectable mechanism

The factory-floor work decomposes the vehicle into tracks, links, wheels, machine/mechanism/chassis state, test state, and source/motion verification. The machine can be observed as a set of relations rather than only represented as a finished tank.

### Lexen WWII — the tank as responsibility under uncertainty

The tank becomes a command interior: driver, gunner, wireless, flotation machinery, movement state, uncertain information, and decisions whose consequences are borne by other bodies. Mechanical state and moral state are coupled.

## Candidate synthesis

A tank is unusually fertile because the same physical variables can support multiple layers without changing object:

```text
TRACK INPUT
-> motion
-> orientation
-> firing geometry
-> exposure
-> crew consequence
-> mechanical stress
-> future position
```

The machine itself can be the interface.

This suggests a useful design target:

> **Do not begin with a tank game. Begin with a tank whose mechanics already create the game.**

## Smallest experiment

A strong first toy would test one question only:

> **Can a tank game be complete when the player only drives the tracks?**

Candidate constraints:

```text
DIRECT INPUT: left track + right track only
NO aim button
NO fire button
MAIN GUN: fires on a fixed recurring cadence
SHOT DIRECTION: inherited from body / turret state chosen by the experiment
WORLD: enough geometry or opposition that steering has consequences
```

The test is not realism. The test is whether track control alone can create:

```text
CONTACT -> CONSEQUENCE -> ADAPT
```

through the coupled demands of movement, orientation, timing, and threat.

If it works, extra crew systems, historical framing, factory visualization, damage, or additional vehicles become optional breadth rather than prerequisites for the toy to be whole.

## Why this seam may be fertile

The three existing lanes provide complementary evidence:

```text
CONVOY gives control compression.
FACTORY gives mechanical legibility.
LEXEN gives human consequence.
```

They can inform one another without being collapsed into one giant project.

## Compact doctrine

> **A good machine can be interface, mechanic, and consequence at the same time.**

> **Start with the machine's coupled obligations. Let content arrive later.**
